# OASIS Route 0.2.1: a smoother first run

Released 2026-11-25 · [GitHub release](https://github.com/FAHTHIZ/OASIS-ROUTE/releases/tag/v0.2.1) · [Full changelog](../../CHANGELOG.md#021---2026-11-25)

0.2.1 comes from trying 0.2.0 the way a new user would. The install was fast, but the path from "it's running" to "a real model answers" had too many dead ends: the demo kept answering after a real model was connected, the console asked you to paste a key you had to find in a file, `setup` ended with "none reviewed yet", and `connect` needed three flags before it did anything. This release removes those steps. It changes no guarantee: nothing paid is enabled or used silently, and imported offers are still never shown as verified.

## Get it

~~~bash
uvx --from git+https://github.com/FAHTHIZ/OASIS-ROUTE@v0.2.1 oasis-route dev --open

# Or the container
docker run --rm -p 8080:8080 ghcr.io/fahthiz/oasis-route:v0.2.1 dev
~~~

Upgrading from 0.2.0 needs no migration.

## The first run now

1. `oasis-route dev --open` starts the server, connects any local model server it finds (Ollama, LM Studio, vLLM, ...), and opens the console already signed in. The printed link carries the key in its `#key=` fragment, which never reaches the server and is removed from the address bar.
2. **Get started** says plainly whether real models are connected or only the demo, and has a **Send test message** button that shows who answered.
3. It lists where to create free, no-card keys (Groq, Gemini, OpenRouter, Cerebras, Mistral, SambaNova, NVIDIA, Cohere, Z.ai, Hugging Face), with one box to paste them all and two checkboxes: these are my accounts, and no billing is set up.
4. Accounts whose routes are held back because their billing is unknown get a one-click "No billing: use it free" button, or `oasis-route billing <provider> free_tier` in the terminal.

From a terminal, `oasis-route connect` with no flags now asks you to paste keys (hidden), shows what it detected and asks the two questions. Scripts keep `--from-env --accept-terms --free-tier`.

## Fixed

- `model=auto` answered with the demo echo after a real provider was connected. Demo providers now step aside for `auto` (gate `demo_provider_superseded`); you can still pin them.
- Route counts treated demo routes as free capacity. `eligible_free` now counts real models only; demo routes are `eligible_demo`.
- `oasis-route setup` printed Python dictionaries and gave no next step on a fresh install.
- `oasis-route providers` labelled the hand-written adapters as imported and advertised.
- `oasis-route doctor` did not warn when only the demo was connected.
- `oasis-route dev` hung with a traceback when its ports were taken, and printed `0.0.0.0` links in Docker.
- Console: narrow paste box, a provider picker that defaulted to a blocked provider, a Discover page about 27,000 px tall, and a "confirm free-tier" prompt for local servers that have no bill.

See the [changelog](../../CHANGELOG.md#021---2026-11-25) for the full list.

## What you get without signing up

Only local models: with Ollama running, `auto` uses it immediately, free and unlimited, at the speed of your hardware. Every hosted free tier needs a key from your own account, which OASIS Route never creates for you. The [onboarding guide](../ONBOARDING.md) lists them.
