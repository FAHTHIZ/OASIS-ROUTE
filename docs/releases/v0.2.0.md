# OASIS Route 0.2.0: the unified gateway release

Released 2026-11-25 · [GitHub release](https://github.com/FAHTHIZ/OASIS-ROUTE/releases/tag/v0.2.0) · [Full changelog](../../CHANGELOG.md#020---2026-11-25)

> OmniRoute's reach and ease of use, governed by OASIS Route's verification, budgeting and honest failover.

0.2.0 turns OASIS Route from a free-tier router for a dozen curated providers into a broad, turnkey LLM gateway. It ships a catalogue of about 220 providers and 2,000 models, one-command onboarding, nine routing strategies, explicit spend modes, a USD budget ledger and ready-made settings for popular coding tools. None of this weakens the existing guarantees. Imported offers are never shown as verified, paid routes are never shown as free, and nothing paid is ever enabled or used silently.

## Get it

~~~bash
# Try it locally (mock providers, no account needed)
uvx --from git+https://github.com/FAHTHIZ/OASIS-ROUTE@v0.2.0 oasis-route dev

# Or run the container
docker run --rm -p 8080:8080 ghcr.io/fahthiz/oasis-route:v0.2.0 dev
~~~

The wheel, source package and CycloneDX SBOM are attached to the [GitHub release](https://github.com/FAHTHIZ/OASIS-ROUTE/releases/tag/v0.2.0), with signed build provenance.

## Highlights

### A catalogue you don't have to type in

About 220 providers and 2,000 models are imported from OmniRoute's public catalogue as advertised data, with provenance on every entry. An imported provider is labelled `advertised` and an imported model `unconfirmed` until a connected account lists it, and imported prices stay `(unverified)`. See [Unified catalogue](../CATALOG.md).

### Turnkey onboarding

`oasis-route setup` detects local servers (Ollama, vLLM, LM Studio, llama.cpp and others), lists the free providers you can connect, and classifies every route as free, paid or unknown, with the evidence behind each label. New projects start in zero-budget mode. Setup never changes a spend policy or billing mode. See [Turnkey onboarding](../ONBOARDING.md).

### Routing you can explain

Nine routing strategies are available, from `strict_quality` (the default) through `lowest_cost`, `most_quota`, `reset_aware` and `diversity`. A strategy only orders routes that already passed every gate. Each decision records the chosen route, the alternatives and every rejection, and `oasis-route explain <request-id>` replays it. See [Routing strategies](../ROUTING_AND_QUOTAS.md#31-routing-strategies).

### Spend modes that ask first

- `zero_budget` (`free_only`) never uses a paid route.
- `bounded_autonomy` answers `402 paid_approval_required` with priced, single-use approval tokens. It never falls back to a paid model on its own.
- `continuity` (`allow_paid`) labels every paid response `PAID FALLBACK` and includes the cost estimate.

See [Spend modes](../ROUTING_AND_QUOTAS.md#21-spend-policy-never-silently-incur-paid-usage).

### A budget ledger with receipts

Projects can set daily, monthly and total USD caps. Each request holds its worst-case cost atomically along with its quota reservation, and is settled exactly once to the actual cost. Every request gets a receipt with a SHA-256 digest. Routes with an unknown cost never run under a budget. See [Budget ledger](../ROUTING_AND_QUOTAS.md#51-budget-ledger-usd).

### Works with your tools

`oasis-route integrate [tool] [--check]` prints paste-ready settings for Claude Code, Codex CLI, Cursor, Cline, Roo Code, Aider, OpenCode, Continue and the OpenAI and Anthropic SDKs, and can test them end to end. Streaming responses and errors now carry the request id and route metadata. See [Integrations](../INTEGRATIONS.md).

### Operator CLI and console

The new `providers`, `models`, `routes`, `quota`, `verify`, `preview`, `decisions`, `explain` and `doctor` commands all accept `--json`. The console adds **Routes**, **Spend** and **Integrations** views, shows cooldowns and budgets in **Capacity**, and has an **Explain** panel for any past request. See [Command line](../CLI.md).

## Fixes and quality of life

- Failover order on PostgreSQL is now deterministic when routes are ranked equally.
- `setup` and `integrate --check` no longer crash when talking to a live server.
- The integration guide reads the right line of the dev key file, and the CLI accepts the whole file.
- An unreachable server or a rejected key gives a one-line explanation instead of a traceback.
- The console navigation wraps on screens narrower than about 1440px instead of hiding sections.
- CI is green again: the attribution scripts pass lint, and the upgrade check runs from a real 0.1.0 commit.

## Upgrading from 0.1.0

Back up the database ([backup and restore](../OPERATIONS.md#backup-and-restore)), then run `oasis-route migrate up` (or `oasis-route serve --migrate`). Migrations 0009 to 0012 add catalogue provenance, route explanations, paid approvals, and budgets with receipts. CI verifies the upgrade from 0.1.0 with live data. There are no breaking API changes: new response fields are additive, and existing spend policies keep their meaning. See [Deployment](../DEPLOYMENT.md).

## What we deliberately did not take from OmniRoute

OmniRoute was a design reference, not a code source. Its catalogue data is imported only as unverified, advertised information. Its silent fallback to paid models was rejected, because it conflicts with OASIS Route's zero-budget and honest-failover guarantees. See the [OmniRoute alignment report](../OMNIROUTE_ALIGNMENT.md).
